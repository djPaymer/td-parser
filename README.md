# TD Parser

CLI-инструмент: на входе Excel со списком сайтов производителей, на выходе Excel с собранными товарами —
URL, название, артикул, описание, характеристики.

Для каждого сайта агент сам выводит регулярное выражение страниц товаров (обход сайта → анализ форм URL →
выбор формы LLM → проверка на скачанных страницах; отклонённый выбор возвращается модели с причиной на второй
раунд, эвристика используется только без LLM), собирает по нему ссылки на товары и разбирает каждую карточку.
Категории не описываются: сбор идёт ограниченным обходом страниц сайта с приоритетом листингов, где товары уже
были найдены, плюс постраничная навигация.

Сайт читается через httpx; если HTML пустой (каталог рисует JavaScript), главная отдаёт 403 или карточки
товаров приходят без описания и характеристик, сайт перечитывается headless Chromium (Playwright).
Если главная страница редиректит на другой домен или является лендингом со ссылками на домен материнской
компании (multigrind.com → ahaas.com), обход продолжается там.

Стек: Python 3.12, httpx, Playwright, BeautifulSoup/lxml, openpyxl, Poetry, Yandex AI Studio (OpenAI-compatible Responses API).

## Требования

- Python 3.12+
- [Poetry](https://python-poetry.org/)
- Ключ Yandex AI Studio (необязателен: без ключа форма URL выбирается эвристикой, качество ниже)

## Установка

```bash
poetry install
poetry run playwright install chromium   # браузер для JS-сайтов; без него парсер работает только по http
cp app/.env.template app/.env
```

В `app/.env`:

```env
APP_CONFIG__AGENT__API_KEY=
APP_CONFIG__AGENT__FOLDER_ID=
APP_CONFIG__AGENT__BASE_URL=https://ai.api.cloud.yandex.net/v1
APP_CONFIG__AGENT__MODEL=deepseek-v4-flash/latest
```

## Запуск

```bash
poetry run python -m app run manufacturers.xlsx products.xlsx
```

Опции `run`:

| Опция | Смысл |
|---|---|
| `--max-products N` | ограничить число карточек на сайт (по умолчанию 0 — собираются все найденные; удобно для быстрой проверки) |
| `--concurrency N` | сколько сайтов обрабатывать параллельно (по умолчанию 3; внутри сайта запросы идут последовательно с паузой) |
| `--no-llm` | не обращаться к LLM, выбирать форму URL эвристикой |
| `--no-browser` | не переключаться на headless Chromium |
| `-v` | подробный лог |

Перед обработкой каждый сайт проходит быструю проверку доступности вне очереди concurrency: мёртвые домены,
TLS-ошибки и 403 получают статус `unavailable` сразу и не занимают слот.

Файл результата пересохраняется после каждого завершённого сайта — длинный прогон можно смотреть по ходу.

Отдельно получить regex для одного сайта (JSON в stdout, с кандидатами и статистикой; `--browser` — читать
сайт через Chromium):

```bash
poetry run python -m app pattern https://www.7leaders.com
```

## Входной Excel

Берётся первый лист. Если в первых строках есть заголовок со словом `url` / `site` / `сайт` / `website`, сайты
читаются из этой колонки, название производителя — из колонки `name` / `производитель` / `brand` (или из первой
другой колонки). Без заголовка — из каждой строки берётся первая ячейка, похожая на URL или домен
(`www.ingco.com` тоже подходит), а имя — первая другая непустая ячейка.

Пример:

| Производитель | Сайт |
|---|---|
| 7-Leaders | https://www.7leaders.com |
| INGCO | www.ingco.com |

## Выходной Excel

Лист **Товары** — одна строка на товар:

`Производитель | Сайт | URL товара | Название | Артикул | Описание | Характеристики | Изображение`

- *Название* — `<h1>` (при его отсутствии JSON-LD, `og:title`, `<title>`, текст ссылки из листинга);
  если заголовок — название серии, а текст ссылки добавляет код модели, берётся расширенный вариант.
- *Артикул* — JSON-LD `sku`/`mpn`, поле «Model/Артикул/型号» из характеристик или первый токен вида `CDLI20012`.
- *Описание* — блок с наибольшей плотностью текста на странице (без меню, крошек, таблиц и ссылочных списков);
  если JSON-LD `description` длиннее — он.
- *Характеристики* — пары `ключ: значение` из двухколоночных таблиц, `<dl>`, списков «Key: value»
  и JSON-LD `additionalProperty`; многоколоночные таблицы (матрицы моделей) добавляются текстом
  `ячейка | ячейка | ...`.

Лист **Сводка** — одна строка на сайт:

`Производитель | Сайт | Статус | Товаров | Regex товара | Источник (llm / heuristic) | Уверенность | Страниц загружено | Комментарий`

Статусы:

| Статус | Смысл |
|---|---|
| `ok` | собраны товары с описанием и/или характеристиками |
| `empty` | сайт прочитан, но брать нечего: LLM не нашла форм URL, похожих на товары (новостной/имиджевый сайт), regex не дал ссылок, либо карточки без описания и характеристик даже в браузере |
| `unavailable` | главная не открылась: DNS, TLS, соединение, 403 (и по http, и в браузере) |
| `error` | остальное; причина в комментарии |

В *Комментарий* попадают формы URL, параметр пагинации, обоснование выбора модели, домен каталога (если он
отличается от входного), переключение на браузер и причина ошибки.

## Ограничения

- Каталоги с товарами в query-string (`/proData.aspx?id=123`) пока не распознаются: формы URL строятся по пути.
- Браузер не спасает, если карточка на сайте действительно пустая (только заголовок и картинка/PDF).
- По умолчанию собираются все найденные товары. Страховки от бесконечных сайтов —
  `APP_CONFIG__PARSE__MAX_LISTING_PAGES` (2000 страниц листингов/категорий на сайт),
  `MAX_PAGES_PER_LISTING` (200 страниц пагинации) и `MAX_STALE_PAGES` (300 страниц подряд без нового товара);
  значение `0` снимает ограничение.

## Конфигурация

Все параметры — переменные `APP_CONFIG__<SECTION>__<KEY>` (читаются из `app/.env`), см. `app/.env.example`
и `app/core/config.py`: секции `FETCH` (таймауты, пауза, User-Agent, TLS), `AGENT` (LLM и бюджет обхода),
`BROWSER` (Chromium: включение, таймаут, число пробных карточек), `PARSE` (лимиты сбора).

## Docker

```bash
docker build -t td-parser .
docker run --rm --env-file app/.env -v "$PWD/data:/data" td-parser run /data/manufacturers.xlsx /data/products.xlsx
```

## Структура

```
app/
  cli.py                 команды run / pattern
  runner.py              один сайт: доступность -> regex -> URL товаров -> карточки (http, при нужде браузер)
  excel.py               чтение списка производителей, запись результата
  agents/
    crawl.py             бюджетный обход сайта
    shapes.py            формы URL и их статистика
    pattern.py           выбор формы (LLM / эвристика), regex, проверка
    llm.py               OpenAI-compatible клиент
  parsers/
    links.py             извлечение ссылок
    paginate.py          определение параметра пагинации
    collect.py           сбор URL товаров по regex
    product.py           разбор карточки товара
  clients/http/          загрузка HTML (httpx)
  clients/browser.py     загрузка через headless Chromium (Playwright)
  core/config.py         настройки
```
