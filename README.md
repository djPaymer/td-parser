# TD Parser

CLI-инструмент: на входе Excel со списком сайтов производителей, на выходе Excel с собранными товарами —
URL, название, артикул, описание, характеристики.

Для каждого сайта агент сам выводит регулярное выражение страниц товаров (обход сайта → анализ форм URL →
выбор формы LLM с эвристическим запасным вариантом → проверка на скачанных страницах), собирает по нему ссылки
на товары и разбирает каждую карточку. Категории не описываются: сбор идёт ограниченным обходом страниц сайта
с приоритетом листингов, где товары уже были найдены, плюс постраничная навигация.

Стек: Python 3.12, httpx, BeautifulSoup/lxml, openpyxl, Poetry, Yandex AI Studio (OpenAI-compatible Responses API).

## Требования

- Python 3.12+
- [Poetry](https://python-poetry.org/)
- Ключ Yandex AI Studio (необязателен: без ключа форма URL выбирается эвристикой, качество ниже)

## Установка

```bash
poetry install
cp app/.env.template app/.env
```

В `app/.env`:

```env
APP_CONFIG__AGENT__API_KEY=
APP_CONFIG__AGENT__FOLDER_ID=
APP_CONFIG__AGENT__BASE_URL=https://ai.api.cloud.yandex.net/v1
APP_CONFIG__AGENT__MODEL=deepseek-v4-flash/latest
```

## Запуск

```bash
poetry run python -m app run manufacturers.xlsx products.xlsx
```

Опции `run`:

| Опция | Смысл |
|---|---|
| `--max-products N` | ограничить число карточек на сайт (по умолчанию 0 — собираются все найденные; удобно для быстрой проверки) |
| `--concurrency N` | сколько сайтов обрабатывать параллельно (по умолчанию 3; внутри сайта запросы идут последовательно с паузой) |
| `--no-llm` | не обращаться к LLM, выбирать форму URL эвристикой |
| `-v` | подробный лог |

Файл результата пересохраняется после каждого завершённого сайта — длинный прогон можно смотреть по ходу.

Отдельно получить regex для одного сайта (JSON в stdout, с кандидатами и статистикой):

```bash
poetry run python -m app pattern https://www.7leaders.com
```

## Входной Excel

Берётся первый лист. Если в первых строках есть заголовок со словом `url` / `site` / `сайт` / `website`, сайты
читаются из этой колонки, название производителя — из колонки `name` / `производитель` / `brand` (или из первой
другой колонки). Без заголовка — из каждой строки берётся первая ячейка, похожая на URL или домен
(`www.ingco.com` тоже подходит), а имя — первая другая непустая ячейка.

Пример:

| Производитель | Сайт |
|---|---|
| 7-Leaders | https://www.7leaders.com |
| INGCO | www.ingco.com |

## Выходной Excel

Лист **Товары** — одна строка на товар:

`Производитель | Сайт | URL товара | Название | Артикул | Описание | Характеристики | Изображение`

- *Название* — `<h1>` (при его отсутствии JSON-LD, `og:title`, `<title>`, текст ссылки из листинга);
  если заголовок — название серии, а текст ссылки добавляет код модели, берётся расширенный вариант.
- *Артикул* — JSON-LD `sku`/`mpn`, поле «Model/Артикул/型号» из характеристик или первый токен вида `CDLI20012`.
- *Описание* — блок с наибольшей плотностью текста на странице (без меню, крошек, таблиц и ссылочных списков);
  если JSON-LD `description` длиннее — он.
- *Характеристики* — пары `ключ: значение` из двухколоночных таблиц, `<dl>`, списков «Key: value»
  и JSON-LD `additionalProperty`; многоколоночные таблицы (матрицы моделей) добавляются текстом
  `ячейка | ячейка | ...`.

Лист **Сводка** — одна строка на сайт:

`Производитель | Сайт | Статус (ok / empty / error) | Товаров | Regex товара | Источник (llm / heuristic) | Уверенность | Страниц загружено | Комментарий`

В *Комментарий* попадают формы URL, параметр пагинации, обоснование выбора модели и причина ошибки.

## Ограничения

- Читается только HTML: сайты, рендерящие каталог JavaScript-ом или закрытые антибот-защитой (Cloudflare и т.п.),
  дадут `error` с подсказкой в комментарии.
- По умолчанию собираются все найденные товары. Единственная страховка от бесконечных сайтов —
  `APP_CONFIG__PARSE__MAX_LISTING_PAGES` (2000 страниц листингов/категорий на сайт) и
  `MAX_PAGES_PER_LISTING` (200 страниц пагинации); значение `0` снимает ограничение.

## Конфигурация

Все параметры — переменные `APP_CONFIG__<SECTION>__<KEY>` (читаются из `app/.env`), см. `app/.env.example`
и `app/core/config.py`: секции `FETCH` (таймаут, пауза, User-Agent, TLS), `AGENT` (LLM и бюджет обхода),
`PARSE` (лимиты сбора).

## Docker

```bash
docker build -t td-parser .
docker run --rm --env-file app/.env -v "$PWD/data:/data" td-parser run /data/manufacturers.xlsx /data/products.xlsx
```

## Структура

```
app/
  cli.py                 команды run / pattern
  runner.py              один сайт: regex -> URL товаров -> карточки
  excel.py               чтение списка производителей, запись результата
  agents/
    crawl.py             бюджетный обход сайта
    shapes.py            формы URL и их статистика
    pattern.py           выбор формы (LLM / эвристика), regex, проверка
    llm.py               OpenAI-compatible клиент
  parsers/
    links.py             извлечение ссылок
    paginate.py          определение параметра пагинации
    collect.py           сбор URL товаров по regex
    product.py           разбор карточки товара
  clients/http/          загрузка HTML
  core/config.py         настройки
```
